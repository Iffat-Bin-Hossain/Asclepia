# Asclepia - Clinical and Patient Operations Portal

## Description

Asclepia is a unified, high-performance healthcare management system designed to streamline clinical workflows between hospital administrators, clinical assistants, and medical practitioners. The platform centralizes doctor registries, patient admission tracking, and real-time clinical analytics into a secure web application, featuring role-based access control where administrators oversee hospital-wide operations and clinical assistants manage assigned doctor registries with strictly scoped permissions and zero cross-tenant data leakage.

## Setup Guide

### Prerequisites
- Node.js (v18.x or later)
- npm (v9.x or later)
- MongoDB (v6.x or later, local instance or MongoDB Atlas URI)

### Installation Steps

1. Clone the repository:
```bash
git clone https://github.com/Iffat-Bin-Hossain/Asclepia.git
cd Asclepia
```

2. Configure environment files:

Create the Backend configuration:
```bash
cp Backend/.env.example Backend/.env
```

Create the Frontend configuration:
```bash
cp Frontend/.env.example Frontend/.env.local
```

### Environment Configuration (.env.example)

#### Backend Configuration (Backend/.env.example)
```env
# Server Configuration
PORT=5000
NODE_ENV=development
FRONTEND_URL=http://localhost:3000

# MongoDB Database Connection
MONGO_URI=mongodb://localhost:27017/doctor_tracker

# JWT Authentication
JWT_SECRET=your_super_secret_jwt_key_here_change_in_production
JWT_EXPIRES_IN=7d

# Administrator Seed Credentials
ADMIN_EMAIL=admin@asclepia.health
ADMIN_PASSWORD=Admin@123
```

#### Frontend Configuration (Frontend/.env.example)
```env
NEXT_PUBLIC_API_URL=http://localhost:5000/api
```

3. Install backend dependencies and seed the database:
```bash
cd Backend
npm install
npm run seed
```

4. Install frontend dependencies:
```bash
cd ../Frontend
npm install
```

5. Run the development servers:

Terminal 1 (Backend API):
```bash
cd Backend
npm run dev
# Server listening on http://localhost:5000
```

Terminal 2 (Frontend Client):
```bash
cd Frontend
npm run dev
# Next.js running on http://localhost:3000
```

6. Access the application:
Open `http://localhost:3000` in your web browser.

Default administrator credentials generated by the seed script:
- Email: `admin@asclepia.health`
- Password: `Admin@123`

## System Architecture

### High-Level Service Overview

Asclepia operates as a decoupled, multi-tier client-server architecture consisting of three core layers:

1. **Presentation Layer (Frontend)**: Built with Next.js (App Router), React Query (TanStack Query v5), and TypeScript. Manages client-side routing, authenticated session persistence, reactive UI states, dynamic query invalidation, and mobile-adaptive interfaces.
2. **Application Layer (Backend)**: Built with Node.js and Express. Exposes RESTful endpoints, enforces JWT verification via custom middleware, executes Role-Based Access Control (RBAC), and sanitizes inbound payloads via Express-Validator.
3. **Persistence Layer (Database)**: Powered by MongoDB using Mongoose ODM. Implements compound indexing for multi-parameter searches (name, condition, date, doctor), referential integrity between doctors and admitted patients, and native aggregation pipelines for real-time dashboard analytics.

### Data Flow Walkthrough

1. **Authentication and Session Lifecycle**:
   - The user authenticates via `POST /api/auth/login`.
   - The server validates hashed passwords via Bcrypt and issues a signed JSON Web Token (JWT) containing user ID and role.
   - For assistants, the server verifies approval status (`status === 'approved'`). Unapproved assistants receive a pending notification and are denied access.
   - The frontend stores the token securely in local storage and attaches it as a `Bearer` token to all subsequent API calls via Axios interceptors.

2. **Role-Based Authorization and Scoped Access**:
   - **Administrators**: Possess unrestricted global access to the Doctors Directory, Patient Registry, Analytics Overview, and Assistant Approvals / Doctor Assignments.
   - **Clinical Assistants**: When an assistant makes any request (e.g., `GET /api/patients` or `GET /api/analytics/dashboard`), the backend retrieves the user from the database, inspects `assignedDoctor`, and strictly filters MongoDB queries to return only patients associated with that specific doctor ID.
   - If an assistant has no doctor assigned, patient data is completely hidden, returning an unassigned status with zero data exposure.

3. **Query Optimization and Search Data Flow**:
   - Patients and doctors are retrieved using server-side pagination, sorting, and multi-field regex searches across indexed fields.
   - Dashboard metrics are computed in real time using MongoDB `$aggregate` pipelines, calculating disease condition distributions, gender breakdowns, and doctor workload metrics without loading unindexed documents into memory.

4. **Continuous Integration and Deployment Pipeline**:
   - **Continuous Integration (CI)**: Managed by GitHub Actions on push or pull request to `main`. Automatically installs dependencies and runs `npm run build` on the frontend and syntax validation on the backend.
   - **Continuous Deployment (CD)**: Automatically triggered on `main` branch updates to deploy the Next.js frontend to Vercel and the Express API server to cloud container platforms with zero downtime.
